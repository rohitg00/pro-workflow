Why auto mode still prompts

Claude Code checks every tool call in this order. The first match decides.

  1. 1deny ruleBlocked, every time
  2. 2ask rulePrompts you, even in auto mode
  3. 3narrow allowRuns, no classifier
  4. 4classifierJudges it against your autoMode rules
  5. 5fallback3 blocks in a row or 20 in a session turn prompts back on

A hook that exits 2 by mistake counts as a block. v3.4 fixes the hooks that did that and teaches the permission tools to prefer autoMode over ask rules.

Notice a correction, pull in what it knows

prompt-submit spots corrections like “don’t do that again” and suggests /learn, and loads relevant wiki pages. drift-detector restates your original goal when, after 6 or more edits, a new prompt looks unrelated to it.

Optional: System 1 classifier

Turn on Laya (local) or Jev (hosted) to catch corrections the keyword check misses, in tens of milliseconds. Off by default. It only suggests /learn; it never allows or denies anything.

Record why it asked

Each prompt and denial is logged. permission-analyst and /permission-tuner read those logs with the transcript’s toolDenialKind and suggest the smallest fix: a narrower ask rule, a hook repair, or an autoMode entry.

Capture the lesson before it is lost

Research, plan, implement

ResearchScout scores readiness and returns GO or HOLD.
PlanPlanner turns requirements into steps.
ImplementPhased commits; Reviewer checks each one.

Each phase has to pass its gate before the next starts. Commands, agents, and skills chain the same way: a command starts an agent, the agent runs skills, and agents hand off through Task, never directly.
